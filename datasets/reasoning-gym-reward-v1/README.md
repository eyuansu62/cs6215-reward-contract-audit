## 正常与条件对照

- **Palindrome**：允许参考答案之外的正确回文。例如同一组`a,a,b,b`，`abba`和`baab`都得1；非回文和错误字母的回文分别有合法的0.02／0.05部分奖励。正奖励不能自动判作漏洞。
- **Prime factorization**：因子重排可得1；只给合数`12`而非质因数，可得合法部分分0.5。对照限于满分的质因数／乘积契约，不保证任意非法字符串都不抛异常。
- **Group anagrams**：有效二维字符串列表的组顺序／组内顺序可变化。但额外诊断发现，列表中的字典也可能通过键迭代得到相同规范化内容并获1分，与严格 list-of-lists 输出要求存在冲突。因此它只是条件语义对照，**不能作一般 schema 安全负例**。该发现标为契约敏感的审阅项，不冒充新确认上游漏洞或训练中的利用。

共检查8个对照候选模块。`eval` 执行边界、契约歧义、可疑行为和继承重复等排除理由保留在`records/controls.json`。没有为了凑数量把源代码改成“正常版”。

## 文件入口

- `dataset.json`：数据集范围、统计、主集／条件对照划分。
- `subjects.json`：固定评分方法、helper、源码与抽取身份。
- `contracts.json`：经源码审阅的任务契约及规范证据。它不是模型生成结果。
- `evidence.json`：最终执行证据、反例、候选修复状态和边界诊断。
- `case-table.csv`：方便浏览的逐版本表。
- `records/`、`notes/`：两路初始源码审阅资料。其pending字段记录执行前阶段；当前状态以`evidence.json`为准。
- `upstream/`、`collection/`：原始文件、commit/tree/Git blob、issue／PR原始元数据、许可证和补充检索。
- `extracted/`：实际执行的原评分方法及必要helper。仅移除代码缩进前缀，完整AST和字符串值与原件一致。
- `results/replay-02/`：最终63项复核；`schema-boundary-diagnostic.json`为单独诊断。
- `audit/`：独立AI源码审阅、契约检查器修正记录和最终完整性检查。
- `source-exposure-inventory.json`：已读源码／函数清单，含被排除候选。

## 离线复核

已验证 Python 3.14.3。复核仅用标准库，不需要安装 Reasoning Gym 或任何新依赖。

```sh
python3 -B repro/verify_dataset.py
python3 -B repro/reproduce.py replay --output $TMPDIR/rg-reward-replay-new
python3 -I -B repro/schema_boundary_probe.py
```

输出目录必须是新目录，原始验证不被覆盖。`repro/prepare.py`可重建相同的抽取材料和输入索引；更新上游来源是另一个显式联网操作，不属于离线复核。

执行的是**原始评分方法与必要纯helper**，不是手写的近似评分器。源码经过AST／命名空间检查，在有CPU和时间限制的独立子进程中运行；仅绑定所列标准库对象。没有导入上游模块、执行类体／构造器／任务生成器、下载题库或调用模型。注解延迟求值，self仅提供原始helper；这些适配明确限制了结论。它不是可执行任意Python的通用安全沙箱，也不等同原issue中的完整seed42包级运行。

## 结论范围与后续使用

当前是**单项目、源码已暴露的开发／可行性集合**，不是未见测试集或LLM泛化证据。bug判断有上游报告、源码契约和方法级反例三类支持；对照和契约由AI辅助整理并独立审阅，不声称人类全面审定或穷尽证明。

复杂数的核心性质是非有限答案拒绝；没有宣称完整验证所有有限数值评分的数学正确性。正常对照也只覆盖声明的性质／输入条件，不代表全函数无其他问题。

未来评测模型时，不能把issue、修复diff、已审契约、反例或标签直接塞进“契约发现”的模型输入；应另行定义只含允许源码与原始任务说明的投影。若要比较独立泛化，应在方法冻结后另选未看函数；本轮所有源码及issue／PR片段都应记为已暴露。当前没有运行任何分析方法，不能报告检测准确率或LLM收益。
