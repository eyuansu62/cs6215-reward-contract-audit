# 一个真实 reward 缺陷的最小契约闭环

选用 Reasoning Gym 已知缺陷 [#544](https://github.com/open-thought/reasoning-gym/issues/544)：`GameOfLifeHaltingDataset.score_answer` 把字符串的 Python truthiness 当成布尔答案的正确性。**具体反例能够区分正确契约和弱契约；现有冻结接口不能忠实表示这项消融，因为它补回了被删除的相等条件。** 本轮只验证这个开发案例，没有改分析器、桥接代码或规则，也没有新的 LLM 契约提取请求。契约、代码和审查由 Codex 辅助完成。

## 1. 案例与可复核反例

- 原版：提交 `49b07130b3fcd12f2d064bba7c43869543a0e7e7`。
- 配对版本：[PR #561](https://github.com/open-thought/reasoning-gym/pull/561) 的冻结提案提交 `4ab6143b1858f5bf09ebe23501a8ffd77c86cdf0`。这里只使用已有提案快照，不将其称为正式发布的修复。
- 主反例：候选 `"False"`，可信参考 `entry["answer"] = "True"`。这是 issue 报告的反向布尔答案问题所对应的最小接口夹具，没有新生成 Game of Life 棋盘。

原版判断：

```python
answer is not None and bool(answer) == bool(entry["answer"])
```

两个非空字符串的 truthiness 都是 True，因此错误答案获得 **1.0**。提案将判断改为 `answer.strip().lower() == entry["answer"].strip().lower()`，同一输入返回 **0.0**。

本轮复用了数据集既有的受限 worker，重放两个版本的反向布尔、`banana`、正确答案三个输入，共六次具体执行。全部与已冻结 `replay-02` 的实际观测一致，源码 AST 身份校验通过，没有导入上游模块、运行构造器或生成器。早期 `records/bugs.json` 中的待执行字段属于原始整理记录，执行证据采用 `results/replay-02` 和本轮新日志。

## 2. 三份契约和预期结果

输入边界固定为原生 `str | None`，可信参考是原生 `"True"` 或 `"False"`，满分阈值为 1。strip/lower 是沿用已审查的布尔契约策略，不是这一轮从短题目重新推断的规则。

| 契约 | 满分必要条件 |
|---|---|
| 正确契约 | 答案是合法布尔 token，且规范化后与可信参考相等 |
| 缺失契约 | 未提供可审计的满分语义条件 |
| 遗漏关键条件 | 仅保留合法布尔 token；删除“与可信参考相等” |

契约变体由 Codex 辅助主动构造作消融，不是假称模型产生过这些错误。

下面的表仅针对主反例 `False / True`，不是对整个函数的通用告警预期：

| 契约 | 原版返回 1.0 时 | 提案返回 0.0 时 |
|---|---|---|
| 正确 | 满分违约：答案与参考相反 | 不触发这项满分违约 |
| 缺失 | 接口按缺失规格策略弃答 | 接口仍弃答；已知实际返回 0 |
| 遗漏相等条件 | 此反例不违反弱契约：False 是合法 token | 不触发这项满分违约 |

缺失行的 Unknown 是“不做契约审计”的行政策略，不是说数学上无法判断 0 是否为满分。已知 reward < 1，本次返回就没有触发满分事件。弱契约下“不违约”也不等于任务答案正确，只说明契约没有表达那一条错误。

另保留 `banana / True` 控制例：原版也返回 1，且 banana 不是合法布尔 token，所以完整和弱契约都能判出这一种违约。因此，**弱契约下整个原函数仍可能合理地告警**，不能预设它必须全局无告警，也不能只看告警数量是否变化来评价契约作用。

## 3. 冻结接口的实际结果

调用的仍是已有 `reward-contract-extraction-v1/tools/downstream.py` 及 `reward-baselines-v1` 分析器；原始方法与规则哈希均未改变。

| 输入契约 | 原版 Semgrep／纯符号 | 提案 Semgrep／纯符号 | 实际传入的语义 |
|---|---|---|---|
| 正确 | 告警／告警 | 无告警／无告警 | 固定 `C_BOOLEAN_FULL` |
| 缺失 | Unknown／Unknown | Unknown／Unknown | 无投影，接口拒绝审计 |
| 遗漏相等条件 | 告警／告警 | 无告警／无告警 | 仍是同一个 `C_BOOLEAN_FULL` |

两个源码版本上，正确／遗漏契约的输入文本确实不同；然而投影对象和实际检测器输入哈希分别完全相同。冻结桥接器仅根据 `answer_kind`、布尔 token 和可信参考标记选择固定契约，不读取 `full_credit_requirements` 的内容。它把遗漏条件的输入也映射成：

> normalized candidate is a Boolean token equal to normalized reference

被删除的参考相等条件因而重新进入分析器。这是**投影不忠实于输入契约**的直接证据，独立于全函数告警是否相同。不能把这种表现记成“LLM 已恢复缺失条件”或“遗漏条件不影响分析”。

原版的纯符号告警使用“新的非空非布尔字符串”这个反例类别，它也能违反弱契约的 token 有效性条件。当前全局告警在这个案例上未必是假阳性，但它不足以识别主反例的错误来源。

缺失契约的 Unknown 同样是冻结封装层的输入政策。Semgrep 的 truthiness 语法模式本身不依赖任务契约；“补入契约后从 Unknown 变成告警”不能被包装为 LLM 新增检测能力。

## 4. 接口可行性结论

**原样完成忠实的三条件静态闭环：不可行。** 当前接口能运行既定完整布尔契约、能拒绝缺失契约，但不能把“合法 token”与“等于参考”作为两个独立义务传递和消融。纯符号检查器按固定语义类工作；Semgrep 适配器还要求契约与固定条款一致，不能把改变说明文字等同于改变执行语义。

**完成开发级可复核闭环：可行，且已完成。** 有真实缺陷、配对提案、已执行反例、先冻结的预期表，以及可直接检查的投影等同证据。18 条具体输入／契约观测均符合预期，三条件的冻结接口输出也符合事先记录的预期。它们来自一个相关的缺陷家族，不是新增 18 个独立样本，也不是 LLM 收益实验。

若以后决定实现，必要的最小接口要求只有三项：

1. 显式保留 `valid_boolean_token` 和 `equals_reference` 两个义务，投影后仍能区分其有无。
2. 无法忠实表示弱契约时返回“不支持／Unknown”，不能自动补成更强的完整契约。
3. 证据标明违反了哪一个义务、对应哪个反例，避免全局告警掩盖消融差别。

以上只是后续接口设计要求，本轮没有实现。没有必要在这一步添加循环、SDK、复杂 formatter 或新的 LLM 摘要功能。
