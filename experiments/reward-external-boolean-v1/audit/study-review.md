## 题目参考

提供的题目只问“Question: Is the passage above toxic?”。它支持二分类语义，但没有规定候选必须序列化为 True/False。可信规范参考是分析环境假设，不等于候选格式要求。两个现有义务都约束候选的字面规范化字符串，不能单从二分类语义推出。因此 null 参考是可辩护的弃答，不能用选单、字段名或已知评分器反补两项条件。

此判断仅限于提供的题目包，不证明完整原生适配／few-shot 请求没有其他格式证据。参考作者披露了形成论证后误读 agent 列表完成摘要的事件；本审查者此前也读过通用 HELM 指标定义。可以独立核对题意论证，但不能将这一过程追认为无偏、无暴露的真人金标准。

## 编排与校验

独立运行 40 个合成测试，通过（绑定 18、编排 19、模型请求 3），代码编译通过；此前另有 8 个绑定检查。没有运行新的实际项目评分、分析器、Semgrep 或模型。

编排要求原件 SHA 和函数 AST 身份一致，具体执行只编译已审阅定义及有限 stdlib 命名空间，拒绝结构化／bool／非有限返回而不转成标量。它明确不是任意 Python 通用沙箱；原生目标异常与准备／范围拒绝分别记录。模型条件必须和封存的 raw／accepted 输出作保留类型的摘要比对，null 参考、弃答和拒收不会被补全。

审查发现并在运行前修复了两点：Unknown oracle 的空集合不能计成一致；封存条件必须实际链接到原始模型契约，而非仅给条件文件自身做 hash。新回归覆盖 null／Unknown 对照时 eligible=0、比较值为 null，以及整数／浮点表示不被悄悄改写。

Semgrep 继续使用固定核心和规则，不做语义过滤；函数／return 覆盖不完整则 Unknown。纯符号全局输入剥离源身份、反例、奖励与标签；指定输入检查不收观测 reward。对 Unknown 的相同结果不算检测成功。

## 待满足条件与边界

`data/dataset-scope.json` 仍为未批准。请求函数在建立输出和任何 subprocess 之前拒绝这个状态；封存不会把 null 参考补成实际模型选择。必须等待明确审批，不能把等待时间或默认选项当作答复。

候选 HELM 函数是同项目的评测政策，不能重称 RL 训练 reward。宽松归一化或前缀接受可能是声明政策，严格 IR 下不兼容也不直接等于上游 bug。题目内容／指标调用关联和实现去重还需最终来源复核。三个函数关联一个题目与一个项目；冻结的符号分析器不支持的 IfExp／helper 仍应 Unknown，不能为取得成绩新增语义。

若用户批准，应先明确修订为评测指标政策兼容性实验、冻结源／协议／参考后再执行；若用户坚持训练 reward，则应报告准入不足。当前只有准备材料，没有独立实验或收益结论。
