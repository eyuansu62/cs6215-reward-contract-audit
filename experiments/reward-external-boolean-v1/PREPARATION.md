# 外部布尔评分函数：待数据类型确认的准备结果

**当前没有启动独立模型／基线实验。** 用户已明确允许仅做有源码依据的参数／参考字段绑定，该部分已经实现并审查。另一个问题仍待用户答复：是否把真实评测评分器纳入原来的 reward 函数测试。准备好的 HELM 函数是评测指标，不能冒称已有 RL 训练用途。

## 已经完成的绑定

新 `native_binding.py` 把原生参数（例如 pred/gold）或单层字典字段映射为既有 candidate/reference Term。它不改写评分源码、不转换 True/False 编码、不增加 helper／解析器／Python 操作支持，也不补齐义务。原 v2 编译器、谓词、底层路径理论和旧结果保持原值。

绑定、原生执行／比较 harness 和提取封存边界合计 40 个合成回归测试通过。独立审查修复了两处记录问题：Unknown／Unknown 不算一致，以及条件文件必须与封存原始模型契约保持类型和内容一致。参考弃答和模型弃答都保留 null。

## 真实项目筛选

两个独立来源整理 lane 已保留固定提交、原始文件、调用关系和排除理由：

- `collection/rg_style/`：五个项目、12 个成功文档／源码文件；包含 RG 包装器、默认实现复制／改写或非标量返回值，没有纳入新的独立训练 reward。
- `collection/native_rewards/`：七个项目、23 个固定源码／说明文件。原生 API 的命名问题在绑定授权后可以单独处理；其余候选仍涉及批处理、结构化返回、带标签答案、逻辑表达式任务或缺少真实布尔任务调用证据。

没有把通用数学 callback 自行配给布尔数据，也没有摘取批输出／结构化结果中的一个值冒充原生标量函数。GitHub 连接器失败、公开索引限流和不存在的路径均保留；固定提交读取使用了只读 git ref 查询与原始文件回退。

## 可供选择的一组 HELM 评测评分器

HELM 固定提交 `63754d05db6f874e41a395880fb573890a13e791` 中：

| 原生函数 | 输入 | 原生返回 | 声明政策 |
|---|---|---|---|
| exact_match | gold, pred 字符串 | int 0/1 | strip 后相等 |
| quasi_exact_match | gold, pred 字符串 | int 0/1 | 规范化标点、冠词、大小写及空白后相等 |
| prefix_exact_match | gold, pred 字符串 | int 0/1 | 允许预测以正确答案开头 |

来源链已对齐：CivilComments 原生把 toxicity≥0.5 的参考写为 True，否则 False；run spec 注册 `get_exact_match_metric_specs()`；该配置的前三项正是上述函数；实际调度传入 `gold.output.text` 和 `completion.text.strip()` 后的 pred。绑定只记录 pred/gold 的对应，不另作编码或答案抽取。

这是**一个项目、一个场景、相关的三种评分政策**，不是三个独立项目。HELM 项目以前曾以 `common/general.py` 工具函数出现过，但本轮评分模块、场景和这些具体评分实现未在旧路径／定义检索中发现。不能声称整个 HELM 从未暴露。

函数源码及实际 helper 原样保留，未把函数改成新签名。候选探针位于原生 metric 的 post-strip 标量边界，包含两个规范参考和每个参考的七类字符串；它们是接口探针，不是假称 42 条 CivilComments 语料注释。None 不在原生调用边界内，未纳入这批探针。

## 参考稿并未强行形成契约

给提取器的原生题目模板是：

```text
{comment_text}
Question: Is the passage above toxic?
```

在相同固定 profile 下，题面支持二元判断，但没有明说候选必须是裸 True/False token。参考稿因此为 `contract: null`。完整 HELM 适配和 few-shot 上下文可能另有格式信息；这里不能把简化的题目包当作整条原生 prompt 的完备说明。

参考稿没有为了接入接口而加上“只输出 True/False”，也没有从数据字段或评分实现自动补条件。作者记录了期间一次 agent 状态列表的偶然暴露；没有隐去这点或宣称完全干净的人工作盲评。null 的论证在该次调用之前已经给出，并经独立审查认可。

若用户选择纳入，本轮应如实测试：模型会弃答，还是对不足的说明作出额外断言；严格 profile 与原生宽松匹配会有哪些差别。后者不自动构成上游 bug，不能用它给模型制造真实漏洞检出收益。冻结分析器对 `IfExp`／helper 可能继续 Unknown，也不会因此扩功能。
