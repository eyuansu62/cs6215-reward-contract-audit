# 固定 Reasoning Gym 契约后的非神经基线结果

本轮已固定契约与评价标准，冻结并运行 Semgrep 和一个有限的纯符号对照，完成同机重放。**这批真实样本没有显示检测收益缺口需要 LLM 填补。** Semgrep 对 7 个已知函数版本的分类均与限定契约标签一致；纯符号检查器对其中 4 个作出正确判断，另 3 个弃答。额外合成诊断表明语法规则确实会误报、漏报，但其中两种误报已经能由纯符号推理消除。

这些是源码已知的开发性结果。规则与检查器在阅读任务和源码后设计，不是盲测，更不是跨项目泛化证据。

## 1. 固定检查什么

目标是：**是否存在正常返回满分（reward ≥ 1）的路径，而答案不满足所声明的满分必要条件。** 不把所有正奖励都当作缺陷，也不把抛异常解释为外部训练框架会发满分。总能返回、外层异常处理、生成器正确性和完整 RL 训练均不在本轮范围内。

| 契约 | 满分必要条件 | 保留的正常行为 |
|---|---|---|
| 布尔判断 | 原生字符串经 strip/lower 后，是与可信 True/False 参考相同的布尔值 | 大小写和首尾空白可忽略 |
| 复数运算 | 候选能解析，实部和虚部有限；可信参考也是有限复数 | 有限但不准确的答案可获正的部分奖励；本轮未审计全部有限数值正确性 |
| 概率 | 有限数值，且与可信 [0,1] 参考的绝对误差不超过 0.0001 | 逗号清理、分数／小数输入，以及低于满分的部分奖励；tol 固定为源码默认值 |
| 回文 | 规范化后是回文，且字符多重集与给定字母完全相同 | 非回文的 0.02、错字母的 0.05 均为合法部分奖励 |
| 质因数分解 | 解析出的因子均为质数，与可信分解的乘积和重数一致 | 忽略顺序、空分隔项和因子空白；0.5／0.01 部分奖励不自动判错 |

输入边界是原生 str/None、固定可信参考、纯评分函数及声明的 helper／标准库；不分析动态初始化、猴子补丁或隐藏 SDK 状态。负例只表示满足上述限定条件，不能称为全局无 bug。

主集是 **7 个函数版本／契约单元、5 个函数家族、1 个项目**：3 个原始缺陷、2 个修复提案版本、2 个正常对照。两个提案在数据冻结时为未合并状态。GroupAnagrams 的格式契约有额外争议，保持排除。已有 63 个执行探针用于核对标签，不算 63 个独立检测案例，也不提供给检测器。

契约与计分规则先冻结，代码与输入随后在主预测前冻结。方法冻结 SHA256：`0925274a7d4b18780fabc611d75c03e0dc9066ef426781ca1a85a2b33edeb1de`。

## 2. 两个 baseline 怎样比较

两者收到同一份精确评分／helper 源码、固定结构化契约、源码导出的标准库绑定和固定参数。预测阶段不读反例值、奖励观测、标签、issue／PR 文本或版本状态；源码哈希 ID 只用于记录。

**Semgrep CE 1.183.0** 使用三个固定、对所有单元相同的语法规则族：布尔 truthiness 相等、非有限距离的指数截断、以较短字符串长度为分母的前缀奖励。简单相邻 isfinite 守卫由原生 Semgrep 模式识别。AST 仅校验输入边界和函数／return 扫描覆盖，不用自己的语义推理过滤告警。保留全部引擎输出；解析、覆盖或运行错误返回 Unknown。无告警只表示没有匹配规则，不是满足契约的证明。

**纯符号对照** 是小型 AST 路径／守卫证书检查器，不是 SMT 求解器或通用 Python 验证器。它追踪有限赋值、分支和正常返回路径；能构造布尔条件的原生语义反例，证明规范化相等、回文和字符多重集守卫，以及经完整源码语法核验的因数解析 helper。未建模的数值调用、复杂 helper、循环或可能影响状态的操作返回 Unknown。无告警需要限定边界内的证书。这个实现的覆盖不足不能代表纯符号技术的理论极限。

计分保留三态：告警、无告警、Unknown。Unknown 不算 TN；正例 Unknown 留在召回率分母。两个方法拥有相同信息，但使用契约的方式和语义能力不同，本轮不声称二者能力匹配。检测方法没有接入实验性 LLM；代码、材料和审查由 Codex 辅助完成。

## 3. 真实版本结果

| 函数版本 | 限定标签 | Semgrep | 纯符号 |
|---|---|---|---|
| CoinFlip 原版 #543 | 有缺陷 | 告警 | Unknown |
| GameOfLifeHalting 原版 #544 | 有缺陷 | 告警 | 告警 |
| ComplexArithmetic 原版 #545 | 有缺陷 | 告警 | Unknown |
| 布尔修复提案 #561 | 契约负例 | 无告警 | 无告警证书 |
| 复数修复提案 #562 | 契约负例 | 无告警 | Unknown |
| Palindrome 对照 | 契约负例 | 无告警 | 无告警证书 |
| PrimeFactorization 对照 | 契约负例 | 无告警 | 无告警证书 |

| 方法 | TP | FP | FN | TN | 正例 Unknown | 负例 Unknown | 正确／总数 | 有确定判断的覆盖率 | 含 Unknown 的召回率 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| Semgrep | 3 | 0 | 0 | 4 | 0 | 0 | 7/7 | 7/7 | 3/3 |
| 纯符号 | 1 | 0 | 0 | 3 | 2 | 1 | 4/7 | 4/7 | 1/3 |

Semgrep 的三次告警分别来自较短长度分母、布尔 truthiness 相等和未被有限性守卫保护的截断。两个提案版本不再触发对应模式。回文、质因数两个 TN 是规则层面的无告警，不应提升为语义验证结论。

纯符号的布尔告警带有路径条件和违反布尔契约的候选语义类别；三个负例分别带有规范化相等、回文／多重集、精确因数解析证书。三个 Unknown 的实际首个阻断点是：CoinFlip 的 `answer.replace` 尚未建模，复数两个版本的 `self.parse_string_to_complex` 尚无可用模型。即使补上这些调用，还需要处理后续数值和控制流；本轮没有为改善分数而继续扩展它们。它们是实现能力缺口，不是 LLM 额外收益。

相对 Semgrep，纯符号在主集没有新增正确案例，少了 3 个确定正确判断。原版与修复版相关，样本很小，不能据此推断 Semgrep 在未知 reward 函数上达到 100%。

## 4. 另外检查会误报、漏报什么

8 个**人工合成、源码已知的诊断案例**与真实主集单独评分，不能当成新增真实项目或泛化收益。

| 诊断 | 契约标签 | Semgrep | 纯符号 |
|---|---|---|---|
| 直接比较字符串 truthiness | 有缺陷 | TP | TP |
| 真实语义相等守卫之后再比较 truthiness | 负例 | FP | TN 证书 |
| truthiness 满分分支放在 if False 内 | 负例 | FP | TN 证书 |
| 紧邻的有效有限性守卫 | 负例 | TN | Unknown |
| 有效守卫与截断之间插入无关赋值 | 负例 | FP | Unknown |
| 守卫后将距离重赋为不可信值 | 有缺陷 | TP | Unknown |
| 有限分支受保护，但非有限分支直接返回满分 | 有缺陷 | FN | Unknown |
| 只返回合法低于满分的奖励 | 负例 | TN | TN（单向契约下的空真） |

诊断合计：Semgrep TP=2、FP=3、FN=1、TN=2；纯符号 TP=1、TN=3、Unknown=4，无 FP/FN。两者均正确 4/8，但覆盖率分别为 8/8 和 4/8。纯符号消除了两个布尔误报，同时在两个 Semgrep 判对的数值案例上弃答，不能只报有利的两项。

这里分开了三类问题：语法模式缺少路径语义；纯符号实现缺少库／数值模型；任务契约需要先明确。第一类中的两个问题已由非神经方法解决，第二类不能自动归因于神经方法的优势。

## 5. LLM 应该放在哪一步

**当前决定是保留这轮基线，不向检测流程接入 LLM，也不再追着 Unknown 加功能。** 这批已知缺陷已被简单规则覆盖，尚没有证据支持“加上函数摘要就有额外检测收益”。合成例子也没有建立这种证据。

如果下一阶段要检验一个最小神经符号方案，优先考察 **从独立任务描述提取结构化契约候选**：LLM 提议答案语义、规范化规则、满分必要条件及允许的部分奖励；确定性检查器依据这些条件检查代码，无法验证则弃答。契约应以题目说明为依据，不能只总结可能有 bug 的评分实现，再把该实现行为当作规范。LLM 输出也不能直接成为金标准。

这一选择的动机是，本轮依赖人手读题和整理契约，而不是已经证明它比人或符号方法更好。后续应在事先留出的新任务家族上比较人工契约与 LLM 契约，分别测契约正确性、下游误报／漏报、Unknown 和人工修订成本；人工契约可以作为规格质量的参考上界。若仍不能带来收益，就报告负结果。当前 7 个版本已经暴露，不能充作那次独立测试。

## 6. 验证、材料和边界

61 个测试方法通过（Semgrep 28、纯符号 28、协议／计分 5）；独立审查另检查 8 个针对不支持语义的案例及 3 个控制例。预冻结发现的局部遮蔽、未知调用被错误视为矛盾、陈旧引用状态、无值注解与异常表达式问题均已保留失败证据，并用保守 Unknown 修复。

主集和诊断集各进行了两次冻结方法运行；解析后的完整分析记录、全部评分指标及扫描参数／源码／规则哈希重放一致。主集 14 条方法结果、诊断集 16 条方法结果分别复核，不合并成“30 个独立真实案例”。没有执行目标评分函数或训练模型，没有新增依赖。原数据集 176 个冻结文件校验通过，数据集和历史 v10 归档哈希保持原值。
