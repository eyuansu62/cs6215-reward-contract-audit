# 显式布尔义务接口：同一案例的 v2 重跑

**本例中的契约消融现在能够忠实执行。** 新接口把“合法布尔值”和“与参考相等”分别表示，只检查明确启用的义务。删除相等义务后，它不再进入编译结果、实际消费者输入或违约记录。现有冻结目录与结果均保持原值。

本轮只修改契约传递、布尔义务选择及证据归属。底层 AST、Term、路径收集、已有原生字符串模型和保守弃答逻辑继续从旧模块导入并校验哈希，没有增加程序操作、循环、数值、helper、SDK 或其他任务支持。契约、代码及审查由 Codex 辅助完成，没有新的实验性 LLM 契约提取请求。

## 修改边界

新契约显式给出义务列表：

```json
{"obligations": ["valid_boolean_token", "equals_reference"]}
```

弱契约只剩：

```json
{"obligations": ["valid_boolean_token"]}
```

其余字段固定原生 str/None 候选、可信 True/False 参考、strip/lower 和满分阈值 1。字段必须明确提供，没有从 `answer_kind`、token 或说明文字推断义务的回退。缺失、空义务、重复、不认识或无法表示的契约返回 Unknown。

`boolean_contracts.py` 负责精确验证／复制 IR 和具体值谓词；`boolean_checker.py` 在旧路径模型上按每个启用义务分别证明或构造反例。没有复制或编辑旧的 AST 分析器。内部旧布尔域标记仅用于原生字符串／参考字段解释；对外编译契约和检查义务来自新列表。

源码中的“与可信参考相等”守卫，可以在数学上证明答案也是合法布尔值。这属于对程序守卫的推理，不等于向弱契约补入相等义务。未启用的契约谓词不会被调用或报告为必需条件。

## 同一真实缺陷与具体反例

沿用 [Reasoning Gym #544](https://github.com/open-thought/reasoning-gym/issues/544) 原版，以及 [PR #561](https://github.com/open-thought/reasoning-gym/pull/561) 的冻结提案快照：

- 原版提交：`49b07130b3fcd12f2d064bba7c43869543a0e7e7`。
- 提案提交：`4ab6143b1858f5bf09ebe23501a8ffd77c86cdf0`，不是已验证发布的修复版本。
- 两个版本、三个既有输入：反向合法布尔值、非法 token、正确答案。没有换任务或增加新的独立测试集。

原版在参考 `"True"` 时，对 `"False"` 和 `"banana"` 都返回 1；提案对这两项返回 0。正确答案 `"True"` 两版本都返回 1。

原版、参考为 `"True"` 时，静态反例核对结果为：

| 提交 | reward | 契约 | 合法值义务 | 参考相等义务 | 记录的违约 ID |
|---|---:|---|---|---|---|
| `False` | 1 | 完整 | 满足 | 不满足 | `equals_reference` |
| `False` | 1 | 遗漏相等 | 满足 | **未启用** | 无 |
| `banana` | 1 | 完整 | 不满足 | 不满足 | 两个 ID |
| `banana` | 1 | 遗漏相等 | 不满足 | **未启用** | `valid_boolean_token` |
| `True` | 1 | 完整 | 满足 | 满足 | 无 |
| `True` | 1 | 遗漏相等 | 满足 | **未启用** | 无 |

缺失契约统一按输入政策返回 Unknown，不猜任务要求。它不是说无法判断 0 是否为满分。提案的错误／非法输入 reward=0，即使某个谓词为假，也没有违反“**满分时**必须满足该谓词”的蕴含条件；本轮没有把假谓词直接当成违约。

## 静态路径、实际返回值与预期逐项核对

全局 `analyze(unit, contract)` 只接收源码与显式契约，不接收观测奖励、保存反例或金标准。它分别报告各义务的 Alarm／NoAlarm／Unknown：

| 版本／契约 | 合法值 | 参考相等 | 全局结果 |
|---|---|---|---|
| 原版／完整 | Alarm | Alarm | Alarm |
| 原版／遗漏相等 | Alarm | 未启用 | Alarm |
| 提案／完整 | NoAlarm | NoAlarm | NoAlarm |
| 提案／遗漏相等 | NoAlarm | 未启用 | NoAlarm |
| 任一版本／缺失 | 无规格 | 无规格 | Unknown |

原版全局会分别生成一个非布尔字符串的合法值反例，以及 `False / True` 的相等反例。弱契约仍可因非法 token 而全局告警，不能把它强行改成全局 NoAlarm 来制造差异。

针对指定输入，`check_witness(unit, contract, answer, reference)` 从同一套已支持的源码路径／Term 推导返回值，再记录启用义务的真值和违约 ID；它没有接收实际奖励的参数，也没有执行目标代码。

另一路复用原有受限 worker，实际执行两个已审阅评分方法，每个三个输入，共六次。每次返回值与旧冻结记录一致。18 项指定输入／契约核对的状态、活动义务、真值和违约 ID 均符合预先固定的预期。其中 12 项非缺失契约检查推导出的返回值与实际执行一致；另外 6 项缺失契约按政策返回 Unknown，没有推导返回值。

具体值 oracle 与静态反例验证共享两个谓词的实现，因此它们是分开的数据／源码路径，**不是两套完全独立的谓词实现**。本轮另外保留了执行前的人工设计、AI 辅助审校预期表和真实返回值检查。

## 消融是否真正保留下来

v1 中两份契约被编译为相同 `C_BOOLEAN_FULL`。v2 的两个源码版本上均验证了：

- 完整和弱契约的编译结果只在显式义务列表上不同。
- 实际消费者输入指纹也不同。
- 弱契约的活动列表和逐义务结果只包含 `valid_boolean_token`。
- 反向合法布尔值不再在弱契约下被标记为相等违约。

Semgrep 源码模式基线保持原冻结结果，没有新规则或契约过滤，也没有将其告警改称逐义务证明。这里的改进是契约接口／消费者正确性，不是已证明的 LLM 额外收益。

## 验证、保存与限制

33 个新回归测试通过，独立审查另做 12 个合成检查。测试覆盖旧投影失败、两个义务单独启用、未启用谓词不调用、错误／非法／正确答案、非满分返回、未知调用／条件、名称遮蔽，以及缺失或不支持的输入。审查发现的大整数常量有限性转换异常已在冻结前用仅对 float 作有限性检查修复，没有新增数值操作支持。

新方法在实际案例重跑前冻结，摘要为 `e6db263e27555a1b68aa15389e94ce6f1cb4468ddf6d2cc6b88b3489fccb49da`。所有前序材料按原清单校验，旧源码和结果未修改。新消费者仅支持一个精确的纯评分函数、无 helper／固定配置参数的原生布尔范围；不支持的程序保留 Unknown，未找到有限候选反例不构成安全证明。

嵌套的旧结果格式器仍保留 `bounded-static-source-path-certificates-v1` 标签；顶层方法明确为 v2。该标签只说明序列化格式继承，不表示旧版已经具备新义务语义。新选择器与谓词消费者仍缺乏机械化可靠性证明。

这完成了**一个已知开发缺陷上的最小接口修复与重跑**。尚未进行新任务泛化、真实人工节省、LLM 新提取或 RL 训练实验，也没有扩展其他分析能力。
