# v2 最终独立审查

结论：通过，无阻塞项。设计、实现、合成回归、主案例、保存字节和最终文档均已复核。

## 已核对的实现边界

显式 IR 必须提供全部固定字段和非空、不重复的已知义务列表；不从类型或自然语言补默认义务。新消费器固定旧 AST／Term／路径模块哈希，只覆盖逐义务证书与反例选择，并增加证据归属。完整与弱契约仅差 `equals_reference`，其实际消费者输入指纹不同。旧内部布尔 profile 仅选择原生字符串／可信参考的模型，对外契约保持显式 IR。源码相等守卫可以证明当前启用的 token 有效性，不等于激活了相等义务。

33 个合成测试独立运行通过，额外 12 个自拟静态检查通过。审查发现的大整数原生字面量有限性转换崩溃在冻结前修复；仅对 float 使用有限性检查，没有增加源语言操作。有限候选没有发现错误时不会被当作安全证明，未知调用、状态修改、未支持语义与预算限制保持 Unknown。

## 主案例与保存核对

- 校验前序 2,805 个清单文件未变，冻结的新代码／输入／worker 哈希与旧 AST 模块哈希吻合。
- 核对六次受限评分执行记录，与旧冻结返回值一致；审查者没有执行目标源码。
- 独立重算 18 条指定输入／契约记录的活动 ID、谓词真值、满分事件和违约 ID。其中 12 条非缺失检查从源码路径推导奖励且与原生实际返回一致，另 6 条缺失规格按政策 Unknown，没有模型返回值。
- 复核六条全局静态结果。原版完整契约分别产生非法 token 和相反合法 token 的源码可行反例；弱契约仅报告有效性。提案版通过源程序的相等守卫证明启用义务。
- 对主反例 `False / True`，完整契约仅违反 `equals_reference`；弱契约未激活该义务，因而不记录该违约。`banana` 在弱契约下仍违反有效性，全局 Alarm 不需要人为消失。
- Semgrep 只引用已有原始源码模式结果，来源文件／摘要吻合；没有新扫描、按契约删告警或逐义务证明的重标。
