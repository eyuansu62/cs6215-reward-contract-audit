# 题目 → LLM 显式义务 → 静态核对：同一真实案例的端到端实验

**本轮已跑通端到端。** 隔离模型从题目说明中选出了 `valid_boolean_token` 和 `equals_reference` 两个显式义务；原始契约经校验后直接进入冻结的 v2 接口，没有人工修订或自动补全。与参考契约比较，六个“版本／具体输入”配对的判断及违约义务集合全部一致。

这证明了这个已知开发案例上的连接和逐义务归属可行，尚未证明 LLM 比参考契约带来更多检测能力。v2 原有分析器、义务实现、所有旧冻结目录和结果保持不变；本轮只增加提取协议、校验和实验编排，没有扩展其他分析功能。

## 模型究竟提取了什么

题目是固定版本的真实 Game of Life halting 提示，其原文询问给定初始棋盘是否在指定步数以内无活细胞，并要求会终止回答 True，否则回答 False。它来自上游构造题目字符串的 AST，仅将实例位置改为 `{max_steps}` 和 `{initial_board}` 占位符，没有执行生成器。

模型只得到：匿名任务 ID、这个题目模板和占位符说明、两种义务的通用定义，以及固定分析环境。参考契约、评分实现、issue／提案身份、源码路径、实际标准答案、反例和观测奖励均没有进入请求。

固定分析环境由研究者提供：候选／参考字段绑定、原生 str/None、可信 True/False 参考、strip/lower 和满分阈值 1。这些并不是模型从题目推断出来的政策。模型的工作是**在已设计的两义务词表中选择题目支持的义务**，不是开放式合成全部任务规格。可信参考这一假设也为相等义务提供了明显的表达支撑。

提示允许只选一个义务，或无法提取时弃答。schema 列出可选 ID，但不要求两个都选；校验只要求所选 ID 有题目原文证据。缺失、无效、空或重复义务不会被修复成完整契约。

## 单次原始提取与参考对照

在提示、校验代码、输入和已有参考契约冻结后，启动一个新的临时 Codex CLI 会话。只调用一次，没有根据响应重试。模型选择：

```json
"obligations": ["valid_boolean_token", "equals_reference"]
```

它分别引用要求输出 True／False 的句子，以及询问棋盘是否在规定步数内停止的问句，解释为答案必须具有正确布尔值。两条引文都与题目正文逐字匹配。输出通过严格 IR 校验，未经人工编辑。

| 对照项 | 结果 |
|---|---|
| 模型与参考的义务集合 | 相同，两个 ID |
| 参考中被遗漏的 ID | 无 |
| 管线自动补入的 ID | 0 |
| 人工修补模型契约 | 0 |
| 题目证据校验 | 通过 |
| 原始契约进入编译／消费者 | 内容与类型保留 |

模型把阈值序列化为整数 `1`，参考稿是 `1.0`。两者在固定语义下数值相等，管线保留原表示，没有为了与参考字节一致而改写。两条件的指纹可能因这一序列化差别不同，不能说模型回答与参考逐字节相同。

这次真实模型输出没有遗漏义务。“遗漏不补全”由包含合法值单独启用、相等单独启用、弃答和坏输入的回归测试验证；不把它写成已经观察到模型遗漏后的实际修复。若模型只选相等，可信规范参考下相等本身逻辑上蕴含合法布尔值，也应区分“显式 ID 少一个”与“语义一定不足”。

## 按具体反例和被违反条件核对

仍使用 [Reasoning Gym #544](https://github.com/open-thought/reasoning-gym/issues/544) 的原版，及 [PR #561](https://github.com/open-thought/reasoning-gym/pull/561) 的已有提案快照。原版提交为 `49b07130b3fcd12f2d064bba7c43869543a0e7e7`，提案为 `4ab6143b1858f5bf09ebe23501a8ffd77c86cdf0`；没有将提案宣称为正式发布修复。

参考均为 `"True"`：

| 版本 | 提交 | 实际 reward | 参考契约的违约义务 | LLM 契约的违约义务 |
|---|---|---:|---|---|
| 原版 | `False` | 1 | `equals_reference` | `equals_reference` |
| 原版 | `banana` | 1 | 两个义务 | 两个义务 |
| 原版 | `True` | 1 | 无 | 无 |
| 提案 | `False` | 0 | 无 | 无 |
| 提案 | `banana` | 0 | 无 | 无 |
| 提案 | `True` | 1 | 无 | 无 |

检查的是“获得满分时必须满足义务”的蕴含关系。提案对错误输入返回 0 时，谓词可以为假，但没有发生满分违约。原版错误合法 token 只违反参考相等；非法 token 同时违反两项。

全局源码分析在两条件下也一致：原版对两个义务分别产生反例，提案以源码相等守卫证明已启用的必要条件。源码相等守卫可以证明合法值，不代表额外启用某个未选择的义务。Semgrep 沿用旧冻结的源码模式参照，本轮没有重配规则、过滤结果或将模式告警改称义务证明。

两条验证路径严格分开：

1. 全局静态分析只收源码与契约；指定反例的静态检查另外收到候选和参考，从旧 AST／Term 路径推导返回值，不接受观测 reward 或期望标签。
2. 既有受限 worker 执行两个已审阅评分方法各三个输入，获得六个真实返回值；不导入整个上游包、不运行构造器或生成器。

12 项条件／反例记录的活动义务、谓词真值、满分标志、违约 ID 和静态返回值均核对通过。它们是六个相关配对，不是 12 个新独立样本。具体 oracle 与静态反例验证共享谓词实现；保留先前人工设计、AI 辅助审校的预期表和真实返回检查，不声称两套完全独立算法。

## 冻结、重放与限制

- 新方法／参考／提示冻结：`ea5e8da2c74637bea061938cdf3c3dc8ea343101dc1f9e44c103d772a1608cd0`。
- 模型原始响应封存：`e3c70b987390a8ca9793b9700600fd2fe8edf818c30e1c6c22fbc69125585959`，先于下游运行。
- 原 v2 方法：`e6db263e27555a1b68aa15389e94ce6f1cb4468ddf6d2cc6b88b3489fccb49da`，保持不变。

九个新增连接／隔离／不补全回归测试通过，代码编译通过。利用同一封存响应重跑下游，两个解析结果摘要逐字节一致，没有第二次模型请求。每次下游重放有六次受限评分执行，不计为新增实验样本。

调用使用 Codex CLI 0.147.0 默认服务，耗时约 7.46 秒；服务 usage 为 27,044 输入 token、197 输出 token，输入包含服务系统上下文。精确底层模型名称未被服务报告，也没有控制温度。完整提示、schema、原始 JSON、事件与 stderr 均保留；事件审计为零工具动作。运行方式按 [OpenAI Codex exec 官方文档](https://learn.chatgpt.com/docs/developer-commands#codex-exec)核对。材料中的契约、代码和审查由 Codex 辅助完成，没有真人效率数据。

同一公开任务和缺陷此前已经暴露，本轮不是盲测；模型也可能有既有知识。检查器仍不验证 Game of Life 演化、步数／拓扑本身或生成器答案正确性，只在可信参考假设下检查两个必要条件。没有新增任务类型、程序语义、数值模型或 LLM 摘要支持。

因此，本轮结论是：**真实题目到显式义务再到反例归属的链路已在这个案例跑通，结果与参考契约一致，未发生自动补全；尚无额外检测收益或泛化结论。**
