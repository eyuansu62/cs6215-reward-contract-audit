# 最小 LLM 契约提取实验

本轮完成了六个新任务题目模板的隔离提取、参考契约对照和冻结分析器的下游运行。**LLM 能生成与参考稿高度一致的契约初稿；没有证实真实人工工作量下降，也没有证实下游检测提升。** 旧基线、规则和分析器代码均保持原冻结版本。

这里的对照是 **AI 辅助制定、按题意交叉审校的研究者参考契约**。用户最初选择独立填写，随后要求助手代为完成；本轮没有真实人工标注、真人修订用时或随机化人机效率实验。不能把结果写成已经验证“节省人工时间”。参考制定与审校本身也可能共享模型偏差。

## 实验怎样隔离

固定使用 Reasoning Gym 提交 `49b07130b3fcd12f2d064bba7c43869543a0e7e7`，选了六个此前未阅读题目内容的任务：字符串同构、赎金信构造、课程先修关系、区间质数计数、数字排序、分数约简。选择是实现前固定的、按文件名和任务概念作出的三布尔／三非布尔定向选择，没有根据结果换题。它们的文件名曾在旧目录树中出现，不能称为文件名未知；预训练数据新颖性也无法保证。题目较短且常见，六条模板的表现不能外推到复杂 reward 规格。

输入是完整题目模板及占位符说明，不是随机生成的具体实例。模型只接收一个匿名任务 ID、相应描述、占位符说明和通用输出 schema。它不接收评分实现、生成器片段、标准答案、参考契约、逐任务评分细则、issue 或 baseline 结果。六题分别启动新的临时会话，没有跨题的模型答案示例；事件审计确认没有使用工具。

顺序为：固定选择与题目包 → 制定、审校并冻结参考稿／提示／校验规则 → 六次提取并封存原始回答 → 阅读评分代码并准备原生源码单元 → 冻结输入后跑下游。实现前规定了停止规则，不按输出改提示、换任务或扩展分析器。

- 提取冻结：`2271f85f77ff26b263d0b543ad43c3ed2dd087e53286698a0a51e34120ea6828`
- 六份回答冻结：`96548066b9f89362d1f05d08591e7bb0ec5427ca40dde9b93c86f357975f6ba5`
- 下游输入冻结：`5d8bf96dc7d4f1912c0aec38ba58c1c6e1d25865bebfa1bceef9a7c70d660e63`

## 提取质量与修订负担

每题比较十个预先规定的字段组，共 60 组：答案类型、布尔 token、集合元素类型、顺序、格式、满分必要条件、明确允许的规范化、容差、部分奖励政策、未规定信息。自然语言按语义核对，不因措辞和参考稿长短不同就判错；这些字段也不是 60 个独立任务。

| 指标 | 结果 |
|---|---:|
| 成功完成的独立模型回合 | 6/6 |
| JSON schema 合法 | 6/6 |
| 通过冻结的完整校验 | 5/6 |
| 明确弃答 | 0/6 |
| 审校认为可保留的字段组 | 59/60 |
| 确认必须实质修改的字段组 | 0 |
| 尚有解释边界的字段组 | 1 |
| 需要处理的证据项 | 1 |

根代理和独立审校代理在互不读取对方判断、未读取下游结果的情况下，逐字段结论完全一致。保留不确定性，没有将其计作“全部正确”。

**T01 的措辞边界。** 模型写了 “Return exactly the Boolean token True or False”。`exactly` 可能额外要求只能输出 token，而题目没有明确规定附带解释如何评分；也可能只是强调 True/False 两个值。建议软化这一处，但不能将它确定判成实质错误。因此字段实质修订量的保守范围是 0–1 组，另有一处证据处理，尚无真人效率结论。

**T05 的证据拒收。** 排序契约正确覆盖了数值排序、按题目给定方向、保留重复项，以及列表中的数字必须是字符串。被拒的是一条方向证据：`instance-specific 'ascending' or 'descending'`。这句话确实出现在提供给模型的 `placeholder_notes`，不是捏造；预先固定的提示和校验器只接受 `question_description` 正文中的证据子串，因此拒收。原始回答和拒收均保留，没有重试或补丁后重新计分。它体现了模型未遵循引用字段要求，也体现了当前证据接口的局限。

六题均没有擅自填写数值容差、部分奖励或大小写／空白归一化规则。区间计数保留了包含端点，排序保留了字符串元素和方向，分数契约没有增设未声明的正分母约定。该小样本支持“可产生待审订初稿”的观察；许多空值／不适用字段本来就容易一致，不能将 59/60 包装成一般契约提取准确率。

## 冻结分析器的下游结果

只增加输入桥接和实验记录。实际导入旧 `reward-baselines-v1` 的 Semgrep 适配器、规则和纯符号检查器，运行前后校验原字节。原方法冻结摘要仍为 `0925274a7d4b18780fabc611d75c03e0dc9066ef426781ca1a85a2b33edeb1de`。

既有接口只能接收若干已固定语义类。本轮三个 True/False 任务能投影到已有的 `C_BOOLEAN_FULL` 满分必要条件；生成器源码支持其可信参考确为原生 True/False 字符串。投影仅检查答案与可信布尔参考的一致性，不检查同构、字母计数或课程图求解是否正确，也不验证完整格式规则。旧 strip/lower 是必要条件的弱化，不能据此声称题目允许这些归一化。

整数计数、数字字符串排序和分数约简不匹配已有契约接口，保留 Unknown，不塞进旧概率／复数等语义类。T05 在 LLM 条件下还因证据拒收而缺少接收后的契约；其参考条件同样因列表类型不受支持而 Unknown。

| 条件 | 可投影任务 | Semgrep 告警 | Semgrep 无告警 | Semgrep Unknown | 纯符号 Unknown |
|---|---:|---:|---:|---:|---:|
| AI 辅助参考契约 | 3/6 | 0 | 3 | 3 | 6 |
| LLM 单次提取契约 | 3/6 | 0 | 3 | 3 | 6 |

**两种条件的 12 个配对方法判断，变化数为 0。** 三个支持任务传给分析器的投影完全相同，纯符号检查器在 `len(answer) > 0` 这个未建模的有序比较处弃答。没有为清除这些 Unknown 扩充语义。

源码准备还发现：T01–T04 都继承此前已暴露的默认 scorer；全部六题只有三个不同评分实现。三个支持任务进一步折叠成 **一个不同的检测器输入**。T05 的原生实现含 `eval`，只保留源码并在准备层标明不支持，没有执行。

因此，下游部分是接口可行性与保持性检查，缺乏独立的评分实现和完整契约正／负例金标准，不能算检测准确率、误报率或真实漏洞检出提升。Semgrep 无告警不等于没有 bug。模型也没有机会让现有检查器利用大部分新提取语义；结果不能据此否定 LLM 契约提取本身。

## 调用、验证与实际结论

使用已登录的 Codex CLI 0.147.0 默认服务，保留了六份提示、原始 JSON、JSONL 事件、usage、返回状态与 stderr。服务未报告精确底层模型名称，不能冒称一个可精确重复的模型版本，也没有控制温度。官方调用与结构化输出用法按 [OpenAI 的 Codex exec 文档](https://learn.chatgpt.com/docs/developer-commands#codex-exec)核对。

六次成功回合的服务计量合计为 151,804 输入 token、1,604 输出 token；输入统计包含服务系统上下文，不等于仅题目文字的 token。单题调用耗时约 7.4–11.3 秒，不是人工用时。另有一次 T01 的 CLI 初始化失败：沙箱中本地状态库只读，尚无模型回合或响应；日志保留，随后以同一冻结提示取得宿主访问权限完成调用，没有根据回答调整重试。

新增 5 个提取协议测试、11 个桥接测试通过，代码编译通过。六个单元、七个函数 AST 静态身份校验通过。参考／LLM 两种下游条件分别重放，完整解析记录和源码／规则字节、扫描参数一致；重放不再次调用模型。原始数据、旧基线和 v10 归档保留不变，没有执行上游任务代码、安装新依赖或开展 RL 训练。

本轮可以报告的是：**六题契约初稿与 AI 辅助参考基本一致，存在一个措辞边界和一个证据字段问题；冻结分析器下没有检测提升。** 真实人工审订成本、未知任务的泛化、精确模型可重复性和更丰富契约的下游价值仍未得到验证。最小实验按计划到此收尾，不继续添加分析器功能。
